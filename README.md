# 元胞自动机沙盒 · CA Sandbox

一个用「元胞自动机」做科学探究的小平台。

不用公式、不解方程 —— 只给每一格定几条最简单的局部规则，然后在旁边看着，
整片火场该烧成什么样，自己就长出来了。这就是**涌现（emergence）**。

## 这是什么

一个 80 × 50 的格子世界。每个格子只知道两件事：**自己是什么**、**邻居在干什么**。
在这之上跑了两个沙盒：

| 沙盒 | 状态机 | 状态 |
|---|---|---|
| 🔥 火灾蔓延 | 正常 → 火星 → 升温 → 燃烧 → 灰烬 | ✅ 已完成 |
| 🦠 传染病传播 | SIR 模型（易感 / 潜伏 / 感染 / 康复） | 🚧 规划中 |

## 火灾沙盒里有什么

### 五个状态，一条链子

```
正常 ──点燃──▶ 火星 ──▶ 升温 ──▶ 燃烧 ──燃尽──▶ 灰烬
```

关键在于**不是「一点就着」**。火要一格一格地爬过中间状态，所以蔓延是有速度、有节奏的，
不会「唰」地一下铺满全屏 —— 这也正是真实火场的模样。

### 消防队是有脑子的

- **从地图四角出发**，不会凭空出现在火场中心
- **只打火线**：已经烧成焦土、「死火」了的格子，理都不理
- **不走焦土**：灰烬不可通行，绕行过去
- **先保命**：万一火追上来了，先撤到安全地面，下一轮再干活
- **停在火边**：贴近到 1 格就动手，绝不踏进火里
- **两种战术**：扑打明火 / 打湿隔离带（火大了会**分兵**，一半扑火一半开带）

还可以直接**关掉消防队**，看看无人发现、任由它烧会怎样。

### 湿隔离带 —— 唯一真能灭火的东西

新增了第 6 个状态 `湿隔离带`。火过不去，但**它会慢慢蒸干**，干了之后火照样冲过来。
所以开隔离带是跟时间赛跑。

### 自己画地图

内置地形编辑器，用笔刷铺植被（枯草 / 湿草 / 灌木 / 针叶林 / 阔叶林 / 岩石），
笔刷宽度可调。画好的地图能**存成 JSON 文件**，下次载回来接着用。

**比例尺：1 格 = 10 米** → 整张图 800 m × 500 m = 40 公顷 ≈ 56 个足球场。
真实山火动辄上万亩，所以这里模拟的是一场「局部火」——重点看**规律**，不看**体量**。

### 导出实验报告

一键导出 **PPT / Word / CSV / JSON**。
PPT 里的火势演化曲线是**原生可编辑图表**，双击就能改数据，不是截图。

## 跑起来

### 方式一：在线演示（最快）

直接打开 **https://luoyuan0101.github.io/ca-sandbox/** —— 不用装任何东西。

### 方式二：本地单文件（不用装依赖）

`docs/index.html` 是一个**完全自包含**的单文件（模型代码已内联），
双击就能在浏览器里跑，功能与正式版一致。

### 方式三：完整 Next.js 项目

```bash
npm install
npm run dev
```

打开 http://localhost:3000

> 首次 `npm install` 需要联网下载依赖，命令行窗口别关。

功能跟正式版一致（画布、速度、消防队、地形编辑器、环境参数全套）。

## 几个可以自己试试的实验

1. **打早打小是真的吗**
   把「出警延迟」从 0 慢慢调到 40，看烧毁面积怎么变。
   → 延迟 18 轮时，结果已经和**没派消防队**差不多了。

2. **隔离带能撑多久**
   选「只开湿隔离带」，观察火线在湿带前停住 —— 然后再看它蒸干之后怎么越过去。

3. **地形决定命运**
   用笔刷铺一片纯针叶林，再铺一片湿草包围的小岛，分别点一把火。

4. **无人之境**
   关掉消防队开关，看火自己烧。这就是「无人发现」的对照组。

## 项目结构

```
ca-sandbox/
├─ lib/
│  ├─ fireModel.ts      ★ 模型核心：状态机、蔓延概率、消防队、地形生成
│  └─ export.ts           导出 PPT / Word / CSV / JSON
├─ components/
│  ├─ FireCanvas.tsx      Canvas 渲染（4000 格）
│  ├─ ControlPanel.tsx    所有参数面板
│  ├─ TerrainEditor.tsx   地形编辑器
│  └─ StatsChart.tsx      手绘 SVG 折线图
├─ app/
│  └─ fire/page.tsx       火灾沙盒主页面
├─ docs/
│  └─ index.html          ★ 单文件演示版（GitHub Pages 部署的这个）
├─ preview/               开发用的零构建版（依赖外部 fireModel.js）
├─ plan.md                项目评审（课程任务 3）
└─ .github/workflows/
   └─ pages.yml           自动部署到 GitHub Pages
```

想改物理效果 → 只动 `lib/fireModel.ts`。
想改界面 → 动 `components/`。

> ⚠️ `docs/index.html` 是**把模型内联进来**的单文件版本。
> 改了 `lib/fireModel.ts` 后，要重新生成它才能在在线演示里生效 —— 见下方说明。

## 更新在线演示

`docs/index.html` 里内联的是编译后的模型代码。改了模型之后：

```bash
# 1. 编译模型
npx tsc lib/fireModel.ts --outDir ./preview --module esnext --target es2020 --moduleResolution bundler --skipLibCheck

# 2. 把 preview/index.html 里的 import 换成内联（见 CONTRIBUTING 或问 AI）
# 3. 复制到 docs/
cp preview/index.html docs/index.html
```

> 为什么要内联？因为 GitHub Pages 上加载外部 ES 模块时，
> 某些情况下（尤其是从 GitHub 网页直接预览 `blob` 链接）模块请求会被拦，
> 脚本整段不执行 → 画布黑屏。内联成单文件后彻底免疫这个问题。
